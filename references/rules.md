# 规则

## JD 拆解

- `surface_problem` 是 JD 明写的；`real_problem` 是“为什么现在招”。
- `problem_type` 只能是止血型 / 建设型 / 转型型 / 补位型。
- `why_now.evidence` 只能引用 JD 原文；没有就标 low。
- 禁止编造融资、裁员、组织调整、前任离职。

## 匹配

- `strengths` 恰好 3 条，每条有 problem / solution / evidence / result。
- `evidence` 必须逐字来自简历；数字不能改写。
- 简历写“参与/协助”不能改成“主导/负责”。
- 总分由校验脚本重算：problem_fit + method_fit + evidence_fit + risk_score。

## 话术

- 3 条最终候选必须来自不同经历、不同能力维度。
- 禁止疑问句和疑问词；不要求 HR 回答技术问题。
- 禁止从个人概要 / 核心成果 / 核心能力 / 自我评价 / 技能清单取证据。
- CTA 指向“要简历/安排投递”，不承诺面试。
- 不写“赋能/闭环/抓手/沉淀/协同/可落地/可复用/全链路/打法/方法论/降本增效”。
- 不自动发送，只给草稿。
